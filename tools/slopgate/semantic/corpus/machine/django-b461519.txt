Fix Cache-Control directive parsing for qualified values

The previous implementation of Cache-Control header parsing did not correctly handle qualified directive values as defined in RFC 9111 (e.g., `private="Set-Cookie"`). This caused directives like `no-cache` or `no-store` to be ignored when they had associated values, leading to incorrect caching behavior.

This change introduces a new utility function `split_directive_names()` in `django.utils.http` that extracts and normalizes directive names from Cache-Control headers, discarding any qualified values. This ensures that directives like `private="Set-Cookie"` are correctly identified as `private`.

Key changes:
- Added `split_directive_names()` to parse and normalize Cache-Control directive names
- Updated `UpdateCacheMiddleware` to use the new function for checking private/no-cache/no-store directives
- Updated `ConditionalGetMiddleware` to use the new function for no-store detection
- Fixed whitespace handling in `patch_cache_control()` to strip whitespace around `=` in directive names
- Added comprehensive tests for qualified directive values and edge cases
