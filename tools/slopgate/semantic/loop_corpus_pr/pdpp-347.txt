## Why

A newcomer reading this repository's front-door documents is told to run commands that fail and to follow links that 404, because two code moves landed without the docs being updated.

The first move: `reference-implementation/`, the runnable server this project ships as its worked example of the specification, was deleted from this repository in #284 and now lives in `PDP-Connect/data-connect`. The second: connector source, the per-platform code that extracts a person's data from one service, now begins in `PDP-Connect/data-connectors`, and this repository's copy under `packages/polyfill-connectors/connectors/` is retained but frozen against direct edits.

Four documents plus one workflow comment still describe the old layout, so the first things a newcomer reads point at a structure that no longer exists.

| File | Stale claim | Effect on a newcomer |
|---|---|---|
| `README.md` section "Reference implementation" | Four `pnpm` scripts to run from the repository root; two links to `reference-implementation/README.md` | Four consecutive `ERR_PNPM_NO_SCRIPT` failures; both links are 404s |
| `CONTRIBUTING.md` intro | Invites connector and reference-implementation code here | Contributor edits the wrong repository; a connector change fails the write-freeze guard with no earlier warning |

| `.github/workflows/polyfill-connectors.yml:32` | Justifies the freeze by citing `DUALHOME-AUDIT.md` | That file is not in this repository on any branch, so the freeze cites nothing |

## What changed

`README.md` now says the reference implementation lives in `PDP-Connect/data-connect` under `reference-implementation/`, links that repository's README, and drops the four dead commands. It adds a pointer to the local collector runbook, the guide for running collection on the reader's own machine so their data never leaves it.

`CONTRIBUTING.md` names both repositories that now hold code and gives each kind of code its own path in `data-connect`: reference-implementation code under `reference-implementation/`, console code under `apps/console/`. It also names the write-freeze guard — the CI check that rejects direct edits to the frozen connector copy — and its `connector-write-freeze-override` escape hatch, the pull-request label that lets a deliberate edit through, so a contributor learns about the rule before CI enforces it. The dead closing link is repointed.

`docs/reference/connector-authoring-guide.md` states that connector source begins in `data-connectors`, and that the authoring rules apply in both repositories.

`.github/workflows/polyfill-connectors.yml` states the reason for the freeze without citing the missing file. The `~150 consuming files` figure in the old comment is itself unverified, so it is dropped rather than repeated as fact. The edit is comment-only; the guard's behavior is unchanged.

## What did not change

No code, no workflow step, and no guard behavior. The write-freeze guard rejects and accepts exactly what it did before. The frozen connector copy under `packages/polyfill-connectors/connectors/` stays in place.
