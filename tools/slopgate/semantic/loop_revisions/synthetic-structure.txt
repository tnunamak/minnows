# Connector runtime migration

## The Amazon connector failure necessitates process isolation

On 2026-08-14, the Amazon connector leaked a file descriptor, causing eleven unrelated syncs to fail for four hours. This incident demonstrates that the current shared-process architecture creates unacceptable operational risk for the broader system.

## Proposed architecture

Each connector will run in its own isolated process. A supervisor will enforce configurable resource limits to prevent a single connector from exhausting system resources or affecting other components.

## Historical context

The connector subsystem has existed since early 2025. It was originally designed for three connectors but has grown to twenty-three. The original design assumed connectors were trusted. Over time, we added retry logic, rate limiting, and a cursor store. Each addition was reasonable in isolation, but the cumulative complexity now demands stronger isolation boundaries.
