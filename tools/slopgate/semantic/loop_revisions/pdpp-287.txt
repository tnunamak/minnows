## Summary

The certification gate runs the PDPP reference implementation's default test suite with a file concurrency cap of 2. This PR changes that constant in `reference-implementation/scripts/run-tests.ts` to 8. The runner already isolates each test file in a separate child process with unique database names, so increasing parallelism does not introduce interference.

## Evidence

Running `scripts/test-accounting/authority.ts` at the same commit with caps of 2 and 8 produced identical receipts: 10,240 assertions, 9,887 passed, 0 failed, 353 skipped, and 1,031/1,031 files completed. Both runs shared the same `manifest_sha256`. The `ri-default/memory-default` suite time dropped from 649.5s to 224.8s (65.3% reduction). The full gate time dropped from 1,202s to 899s (25.2% reduction).

I reproduced these results on a separate clone under heavier load. Cap 2 took 1,079s; cap 8 took 431s (60.1% reduction). Receipts matched exactly, including the `manifest_sha256` (`f1645c5c45a19140...`).

## What was NOT measured

- **The `ri-default`/PostgreSQL profile.** A concurrent session used the shared test database, preventing a clean comparison. The per-file database naming logic suggests safety, but this path was not directly measured.
- **CI runner performance.** Measurements occurred on 24-core development machines, not the production CI runner. Users can override the default via the `PDPP_TEST_CONCURRENCY` environment variable.
- **Optimal cap value.** Only caps 2 and 8 were tested. This PR does not claim 8 is optimal, only that it improves upon 2.

## Next bottleneck

The `polyfill-connectors` suite remains the largest contributor to gate time, taking roughly 450s. It caps its own internal concurrency independently of `run-tests.ts`, so this change does not affect it. Further speedups require raising that suite's internal cap.
